> [!WARNING]
> This port uses experimental U-Boot and NAND driver stacks.
> While the first public release already includes **many** safeguards that kick failures back to FEL,
> a chance of bricking remains higher than for stable ports.

> [!WARNING]
> Because of different partition layouts, the current OTA tools
> **do not** support automatic backup and restore of the vendor firmware at this time.
> The flashing process is only one-way **at this time**.

> [!WARNING]
> U-Boot verifies NAND chip against the whitelist - mismatch will result in reboot to FEL.
> The chip in Wooboobox T12 is known to be **0xD8:0x81** and it's the only one whitelisted.
> Older AX1800 dongle by the same manufacturer shipped **0xD8:0x91**, so it may still appear in some dongles.
> Both are GigaDevice clones (original VID **0xC8**).
> In the future, mismatch will be detected before OTA update is allowed to be flashed.

### V851S

V851S, sometimes referred to as "the magic transcoding dongle", are dongles based on Allwinner V851S chips.  
They feature Cortex A7 CPU and a unique ability to transcode H264 streams, required for full functionality of AirPlay mirroring.

The most common variant features V851S3(a package with 128MB RAM), 128MB SPI-NAND and AIC8800D80 and is sold as **Wooboobox T2** and it's different rebrands, including a recent rebreand called **Carlinkit Mini Ultra 6**.

There is a known legacy variant with 64MB RAM, SPI-NOR and RTL8733BS which is not supported, but may be supported in the future. 

### Enter FEL from Wooboobox firmware

> [!WARNING]
> The current `wizard.py` revision has not yet been tested through a full flash starting from vendor firmware. Use the manual procedure below to enter FEL, then start the wizard with `--already-fel`. For future updates from CatPlay, use `--refresh`.

Connect ADB to the device over Wi-Fi:

```console
$ curl -X POST --data 'x' '192.168.1.101/cgi-bin/submition.cgi?filename=a;adbd&' >/dev/null 2>&1 &
$ sleep 2
$ adb connect 192.168.1.101:5555
```

Request FEL and reboot:

```console
$ adb shell 'echo 0x07090108 0x5aa5a55a > /sys/class/sunxi_dump/write'
$ adb shell 'cat /sys/class/sunxi_dump/write'
$ adb reboot
```

### Flashing wizard

> [!NOTE]
> All steps require the device to be connected to the PC over USB.

Install dependencies:

```console
$ python3 -m pip install pyusb paramiko cryptography pylibfdt
$ sudo apt install -y libusb-1.0-0 squashfs-tools swig python3-dev build-essential
```

Run the scripts from the `tools/` directory of an unpacked firmware bundle:

```console
$ cd tools/
```

#### Refresh a device already running CatPlay

```console
$ python3 wizard.py --v851 --refresh
```

#### Flash after entering FEL manually

After the device has entered FEL using the procedure above, run:

```console
$ python3 wizard.py --v851 --already-fel
```

#### Flash when the device is already in recovery

```console
$ python3 wizard.py --v851 --already-recov
```

#### Boot recovery without flashing

```console
$ python3 wizard.py --v851 --no-flash
```

### After flashing

The device reboots into CatPlay. Its Wi-Fi networks are `C2A_AP` and `C2A_P2P`; the password is `lovec@ts`. SSH is available at `root@192.168.50.2` over the device Wi-Fi. You will need to pair your phone again.

## Capturing logs

If CatPlay does not work with your car, reproduce the issue and collect `/var/log/catplay.log` and `dmesg` from the device. You can save the latter on the device with:

```console
$ dmesg > /var/log/kernel.log
```

Include both logs and the car model when reporting the problem.
